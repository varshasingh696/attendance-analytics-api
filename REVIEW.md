# REVIEW.md

Defects found in the starter `app/main.py`. All of them are fixed in the final file.

| # | Where | What is wrong | How I'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Compares the **floored** minutes with `> 10`, so 09:40:01 (10 min 1 s) gives 10 and is treated as not late. Grace must be "strictly more than 10:00". Seconds are not truncated first. | Shift 09:30, punch-in 09:40:01 must give `late_minutes = 10`; the starter gives 0. | Work in whole seconds: late only if `delta > 600 s`, then `delta // 60`. Instants are truncated to seconds first. |
| 2 | `compute_late_minutes` | Takes the shift start from `punch_in.replace(...)`, i.e. from the punch's own date in the punch's own (naive, server-local) zone. Not IST, and overnight shifts (22:00-06:00, punch-in 02:00) use the wrong day. | Run on a UTC server: 09:40 IST is 04:10 UTC, so "shift start 09:30" is applied to the wrong clock. Overnight punch-in at 02:00 gives a late value of about -20 h, i.e. 0. | `attendance_date()` (R1) picks the IST attendance day, `shift_start_dt()` builds the shift start in IST for that day. |
| 3 | `compute_work_hours` | `round()` is banker's rounding on a float, not half-up (R4). It also breaks the half-day boundary (R5). | 450 s = 0.125 h: `round(0.125, 2)` is 0.12, but half-up gives 0.13. | `Decimal` quantize with `ROUND_HALF_UP`. `half_day` uses the rounded value (`< 4.50`). |
| 4 | `compute_overtime` | No 30-minute minimum (R3), returns every positive minute. Overnight shifts are not handled (end is the next day). The `punch_out` it receives is naive, so `punch_out - end` raises `TypeError` (naive vs aware). | Punch-out 18:35 on a 18:30 shift returns 5, should be 0. Calling it with a naive datetime crashes. | `compute_overtime()` uses aware datetimes, `shift_end_dt()` adds a day for overnight shifts, floor minutes, 0 if under 30. |
| 5 | `punch_in` | Unknown `emp_code`: `emp` is `None`, then `emp["shift_start"]` raises `TypeError` -> 500 instead of 404. | POST punch-in with `emp_code: "NOPE"`. | `get_employee()` returns 404. |
| 6 | `punch_in` | Check-then-insert race: `find_one` then `insert_one`. Two parallel requests both pass the check and create two records. | Fire 10 identical requests in parallel: more than one 201. | Unique index `(emp_code, date)`, `insert_one`, `DuplicateKeyError` -> 409. |
| 7 | `punch_in` | Time handling: `datetime.fromtimestamp(ms / 1000)` and `datetime.now()` are naive server-local time. The date is taken from that local time, not IST, and is not truncated to seconds. `if body.punched_at` treats `0` as "not given". | A punch at 20:00 UTC (01:30 IST next day) gets the wrong `date` on a UTC server. | `ms_to_dt` / `dt_to_ms` with aware UTC, truncate to seconds, IST date via `attendance_date()`, `is not None` check. |
| 8 | `PunchInIn`, `EmployeeIn` | No validation: `status` is any string (ABSENT/LEAVE/garbage accepted), `punched_at` accepts seconds-looking values, floats, strings, `emp_code`/email/`HH:MM`/date formats are unchecked, `shift_start == shift_end` allowed. | POST `status: "FOO"`, `punched_at: 1700000000`, `joined_on: "2026-02-30"`: all return 2xx. | Pydantic models with enums, patterns, `StrictInt` + range for epoch ms, real-date validator, shift check (all give 422). |
| 9 | `punch_in` response | Returns `id` (the `_id` as string) and raw datetimes instead of epoch ms. `_id` must never leave the API. | Compare the response with the `AttendanceRecord` schema. | `record_out()` returns only contract fields, instants as epoch ms. |
| 10 | `create_employee` | Check-then-insert race on `emp_code` (needs a unique index). `created_at = datetime.now()` is naive local time and is returned as a datetime, not epoch ms. | Parallel duplicate creates give two 201s. | Unique index + `DuplicateKeyError` -> 409; `created_at` is aware UTC and returned in ms. |
| 11 | `list_employees` | `skip = page * page_size` skips the first page (should be `(page - 1) * ...`). `total` ignores the department filter. No sort by `emp_code`. No limits: `page=0`, `page_size=100000` accepted. | Page 1 returns what should be page 2. `total` stays 100 when filtering. | Fixed skip, filtered `count_documents`, `sort("emp_code")`, `Query(ge=1)` and `le=100`. |
| 12 | `list_attendance` | Loads the **whole collection** into Python, sorts and slices in memory (slow and memory-hungry at 100k docs). Sort lacks the `emp_code` tie-break. `page=0` slices with negative indexes. Returns `_id` as `id`, datetimes, no `date_from > date_to` check, status not validated. | 100k records: slow response and high memory. | DB-side `find` + `sort` + `skip` + `limit`, `count_documents(filter)`, validation, `record_out()`, supporting indexes. |
| 13 | startup / client | No indexes are created at all (every list is a collection scan, uniqueness cannot be enforced). `MongoClient` has no timeout and no `tz_aware`. A hard-coded fallback URI is baked in. | Explain shows `COLLSCAN`; with Mongo down every request hangs. | Idempotent index creation in the lifespan hook, `tz_aware=True`, `serverSelectionTimeoutMS`, env-driven config. |
| 14 | `/health` | Always returns ok, even when MongoDB is down. | Stop MongoDB, call `/health`: still 200. | Pings MongoDB, returns 503 on failure. |

## Looked at and judged fine
- `load_dotenv()` does not override real environment variables (default `override=False`), which is what the contract wants. I kept that explicitly.
- `find(q, {"_id": 0})` in `list_employees` and `doc.pop("_id")` in `create_employee`: they correctly keep `_id` out of the response.
- `status_code=201` on the two create endpoints matches the contract.
- Filtering `date` with string `$gte`/`$lte` is correct because `YYYY-MM-DD` sorts the same as the dates it represents.
